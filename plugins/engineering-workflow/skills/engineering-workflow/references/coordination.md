# 调度与交接

使用项目适配中的资料入口和项目 Cycle 规则。没有既有规则时，在 cycle_root 下建立稳定的日期主题目录，保存基线、契约、任务与实际验证报告；纯工程工具或文档任务标明业务门禁不适用的理由。

先固化 HEAD、分支、已修改/未跟踪文件和内容摘要。一个 Cycle 对应一个目标；恢复时以文件产物和证据为依据，旧验收保留。任务契约可取自 [模板](../assets/task-contract.md)，交接可取自 [报告模板](../assets/agent-report.md)；项目已有模板时优先沿用。

## 按改动面选择角色

产品和架构先明确目标、模块、接口、数据副作用与验收；已有冻结契约可以复用。界面由 frontend 实现，API/用例由 backend 实现，数据结构/迁移/事务/备份由 database 负责；test 负责可重复证据，delivery 负责构建/发布工具和授权内交付。

orchestrator 分配任务和路径；reviewer 独立审查规格与差异；debugger 复现和定位，由原能力负责人修复；architecture_auditor/ui_auditor 按实际影响只读检查；verifier 核对版本、接收证据和适用门禁。通用职责以 [原生模板目录](../assets/agents/) 为准，项目约束从 role_documents 加载。

## 派发和写入

派发消息携带可直接执行的契约：任务编号、角色、唯一负责人、Cycle、输入/输出、允许/禁止路径、依赖、接口/数据不变量、验收、证据和交接对象。职责与路径缺失时只读调查并返回 NEEDS_CONTEXT。

共享配置、路由、全局组件/样式、接口、数据库和部署文件指定唯一写入人并串行。独立目录且无未满足依赖时，按运行时/项目规则允许范围并行；实现与独立测试不得同时写同一文件。

交接落到 Cycle：输入依据、产物、实际命令及退出码、证据、风险、接收对象和下一动作。消息通知不能替代文件交接。测试失败不降低门禁；范围外依赖记录 NEEDS_CONTEXT，交回调度。

## 验收与交付

实施后派发独立审查 Agent，对照契约和项目规则读取本次真实差异/新增文件，修复重要问题再复验。核对证据对应实际版本；测试命令取自项目实际配置。

工具初始化、TOML/引用合法、插件 installed/enabled、会话发现、自定义角色名称路由、业务测试、浏览器验收和发布是不同验证项。缺哪个记录哪个，不用静态结果替代运行结果。依据项目规则和用户既有授权执行发布；未回复不是批准。没有发布目标的任务在项目接入/验收完成后结束，不进入应用部署。

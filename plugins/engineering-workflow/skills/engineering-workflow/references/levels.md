# 执行级别与上游技能

级别只控制工程流程的投入，不能在当前会话中更改模型推理强度。用户明确指定的级别优先；未指定默认“一般”。任何级别都遵守项目规则、保护现有改动，并对实际修改做相称的验证。任务范围扩大时告知用户并升级流程；不因级别降低必要的安全或正确性检查。

| 级别 | 适用情况 | 执行方式 |
| --- | --- | --- |
| 简单 | 单点、低风险、可快速核实的问答或改动 | 直接调查、处理、验证；不创建 Cycle、不派发角色、不默认调用上游技能。 |
| 一般（默认） | 有明确范围的常规功能、缺陷或方案 | 读项目约束，给出简短方案，单一负责人实施并运行相关检查；需要时选用一个直接相关的上游技能，如 `diagnosing-bugs`、`tdd` 或 `code-review`。跨会话工作才记录轻量任务契约。 |
| 工程 | 跨模块、高风险、多人协作或需要可恢复交接的任务 | 初始化/核对适配，建立 Cycle 和任务契约，按需派发角色，保存证据并独立审查。按任务需要走需求澄清、规格/任务、实施、审查阶段；不固定执行完整链条。 |

工程级对应关系：上游 `grill-with-docs` 的需求与领域澄清对应 Cycle 基线；`to-spec`、`to-tickets` 对应规格和任务契约；`implement` 对应实施与测试；`code-review` 对应独立审查。这里复用的是阶段与产物，不表示自动调用这些技能。部分上游技能要求用户显式调用，部分还要求目标仓库先完成 `setup-matt-pocock-skills`；直接调用时须遵守各自的触发条件和前置条件。

用户可以说“按简单级处理”“按一般级处理”或“按工程级处理”。如用户直接指定某个 Matt Pocock 技能，应遵循该技能本身的适用条件和指令；执行级别不替代技能内容。`setup-matt-pocock-skills` 是每个业务仓库自己的配置流程，不在安装插件时自动改写目标仓库。

Codex 的模型推理强度由用户所选模型和运行时配置控制，不由本插件的 Skill、项目适配或 hook 强制设为高档。希望减少模型计算开销时，可在 Codex 客户端为简单级选择较低档、一般级选择中档；工程级也由用户自行选择所需档位。模型或客户端不支持相应档位时，以实际可选项为准。这里的三级只影响工作流步骤与产物。
